## Temuan prioritas

### P1 — Production build lokal tidak bisa diverifikasi

`npm run build` berhenti saat pengumpulan konfigurasi route API karena `DATABASE_URL` tidak tersedia. Ini bukan bukti deployment live rusak; endpoint live `/health` dan halaman publik merespons normal. Build harus diulang pada environment yang memiliki konfigurasi database non-produksi atau memakai environment CI yang aman.

### P1 — Dependency security

`npm audit` melaporkan 13 vulnerability, termasuk advisory critical pada Next.js dan beberapa advisory high pada `braces`, `deepmerge-ts`, `mysql2`, serta `mariadb`. Jangan menjalankan `npm audit fix --force` langsung karena npm melaporkan potensi perubahan major pada Tailwind/Prisma. Perlu upgrade terencana, lalu type-check, test, build, dan smoke test ulang.

### P2 — Lint belum operasional

Project memakai `eslint@9.39.5`, tetapi konfigurasi masih `.eslintrc.json`. ESLint 9 mencari flat config dan berhenti sebelum memeriksa source. Perlu migrasi konfigurasi atau pin ESLint ke versi yang kompatibel dengan konfigurasi lama; pilih satu pendekatan dan kunci di package-lock.

### P2 — Password reset belum selesai

`app/api/auth/forgot-password/route.ts` masih memiliki TODO untuk pengiriman OTP WhatsApp. Fitur harus diberi status jelas di UI/API dan tidak boleh dianggap sebagai alur reset produksi sampai gateway dan rate limit tersedia.

### P3 — Root repository terlalu ramai

Root berisi beberapa dokumen planning/status yang tumpang tindih (`Plan.md`, `task_plan.md`, `progress.md`, `findings.md`, `todolist.md`, `CHECKPOINT.md`, `IDEA.md`). Jangan menghapus atau memindahkan tanpa keputusan pemilik karena sebagian menjadi catatan historis. Kandidat rapih: arsipkan catatan historis ke `docs/project-history/`, pertahankan satu `docs/PROJECT-STATUS.md`, dan perbarui tautan internal.

Aset screenshot juga tersebar di `screenshots/`, `public/tutorial/`, `public/presentasi/`, dan `docs/manual-pengguna/`. Ini perlu inventarisasi dan deduplikasi terpisah; jangan menghapus aset sebelum memastikan tidak direferensikan.

## Batasan audit

- Tidak melakukan login karena kredensial tidak disediakan dan tidak boleh ditebak.
- Tidak mengubah database live.
- Tidak menjalankan seed/reset/migrasi terhadap database.
- Audit UI terautentikasi, role matrix, transaksi, POS, approval, dan laporan memerlukan akun uji yang aman atau environment staging.
- Audit visual/responsive mendalam belum menggantikan pengujian manual pada perangkat nyata.

## Rekomendasi urutan tindak lanjut

1. Sediakan environment staging/CI dengan `DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`, dan `NODE_ENV`; ulangi build.
2. Migrasikan ESLint ke flat config atau pin versi ESLint secara sengaja; jadikan lint gate CI.
3. Buat rencana upgrade dependency keamanan tanpa `--force`, mulai dari Next.js dan lockfile.
4. Rapikan dokumentasi dan aset setelah inventarisasi referensi, dalam commit terpisah dari perubahan fitur.
5. Jalankan E2E berdasarkan role: SUPERADMIN, PIMPINAN, MANAGER KPAK, STAFF KPAK, MANAGER retail, STAFF retail.
6. Tambahkan regression test untuk password reset setelah provider OTP dan rate limit diputuskan.
